> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** upstream v1.0.1 を当フォークの新しいベースに据え、フォーク独自の 3 機能（KPI Goals タブ / 埋め込み JSON の `<` エスケープ / Playwright E2E）を新しいモジュール構成の上に再実装する。

**Architecture:** `git merge` / `git rebase` は使わない。`v1.0.1` タグから新ブランチを切り、独自変更を「担当モジュール」へ手で書き直す（upstream `MIGRATION.md` の指示に従う）。計算ロジックは `claudestats_core/` の該当モジュール、設定は `claudestats_core/settings.py` の seam、UI は `templates/` の実ファイルに置く。検証は upstream 同梱の unittest スイート（pytest で実行、v1.0.1 で 252 passed）を基準線とし、各機能ごとに新規テストを足す。

**Tech Stack:** Python 3.10+ / unittest + pytest / Chart.js（`templates/` にバンドル） / Playwright (TypeScript, pnpm) / pre-commit (ruff, prettier, rumdl)

**Spec:** `docs/superpowers/specs/2026-08-18-upstream-v1.0.1-migration-design.md`

## Global Constraints

- **upstream 管理ファイルは Edit/Write ツールで編集しない。** 対象は `extract_stats.py`、`claudestats_core/**`、`tests/**`（既存ファイル）、`templates/**`。グローバル PostToolUse hook (`~/.claude/hooks/quality-loop.sh`) が `ruff format` / prettier をファイル全体にかけ、upstream との差分が数万行に膨れるため。**Bash 経由の置換スクリプトで編集する**（下記テンプレート参照）。新規作成するファイル（`tests/test_*.py` の新規分、`e2e/*.spec.ts`、docs）は Write で構わない。
- **置換は必ず出現回数を検証してから適用する。** 標準テンプレート:

  ```bash
  python3 - <<'PY'
  from pathlib import Path
  p = Path("claudestats_core/aggregate.py")
  s = p.read_text(encoding="utf-8")
  old = "<置換前の文字列>"
  new = "<置換後の文字列>"
  assert s.count(old) == 1, f"expected 1 occurrence, found {s.count(old)}"
  p.write_text(s.replace(old, new), encoding="utf-8")
  print("ok")
  PY
  ```

- **テスト実行には `config.json` が必要。** `extract_stats.py` は import 時に `load_config()` を呼び、`config.json` が無いと `SystemExit(1)` になる。リポジトリ直下に `config.json`（`config.example.json` のコピーで可、gitignore 済み）を置いてから `pytest` を回す。
- **ベースラインは 252 passed + 22 subtests。** 各タスクの完了時にこの数以上が通ること。`fix(parse): take the last line's usage` 等の upstream 修正により旧フォークとは数値が変わるが、これは回帰ではない。
- **タブ ID は `[a-z]+` のみ。** `tests/test_tab_aliases.py` がタブ ID を `id:\s*'([a-z]+)'` で抽出するため、アンダースコアを含む ID は使わない。KPI タブの ID は `goals`。
- **upstream への PR は禁止**（プロジェクト `CLAUDE.md`）。`gh pr create` は必ず `-R ywatase/claude-code-stats` を指定する。
- **コミットメッセージは日本語**、prefix は `feat/fix/docs/style/refactor/chore/test/perf`。末尾に `Co-Authored-By: Claude Opus 5 (1M context) <noreply@anthropic.com>`。

## Task 2: 埋め込み JSON エスケープの一元化

**Files:**

- Modify: `extract_stats.py`（`generate_dashboard` 周辺、`_locale_script_tag`、`generate_session_pages`、`generate_project_pages`）
- Test: `tests/test_embedded_json_escape.py`（新規）

**Interfaces:**

- Produces: `extract_stats._embed_json(obj, **dumps_kwargs) -> str` — `json.dumps` の結果の全 `<` を `<` に置換した文字列を返す。`<script>` ブロックに直接埋め込むすべての JSON はこの関数を通す。

**背景:** upstream v1.0.1 は 4 箇所で `.replace("</", "<\\/")` を行うが、`__PROJECT_DATA__`（`extract_stats.py` 付近 1657 行）は**無エスケープ**。さらに `</` のみの対策は、埋め込みテキストが `<!--` と `<script` を両方含む場合に HTML トークナイザが script-data-double-escaped 状態へ入るため貫通する。

- [ ] **Step 1: 失敗するテストを書く**

`tests/test_embedded_json_escape.py` を新規作成:

```python
"""Embedded JSON must never carry a raw "<" into an inline <script> block."""
import json
import sys
import unittest
from pathlib import Path

ROOT = Path(__file__).resolve().parent.parent
sys.path.insert(0, str(ROOT))

from extract_stats import _embed_json  # noqa: E402

# "<!--" followed by "<script" puts the HTML tokenizer into the
# script-data-double-escaped state, where "</script>" alone no longer
# closes the tag. Escaping only "</" is therefore not sufficient.
HOSTILE = '<!-- <script> </script> --> </ScRiPt >'


class EmbedJsonTest(unittest.TestCase):
    def test_no_raw_angle_bracket_survives(self):
        out = _embed_json({"text": HOSTILE})
        self.assertNotIn("<", out)

    def test_value_round_trips_unchanged(self):
        out = _embed_json({"text": HOSTILE})
        self.assertEqual(json.loads(out)["text"], HOSTILE)

    def test_dumps_kwargs_are_forwarded(self):
        out = _embed_json({"a": 1, "b": 2}, separators=(",", ":"))
        self.assertEqual(out, '{"a":1,"b":2}')

    def test_non_ascii_is_not_escaped(self):
        # ensure_ascii=False is the project-wide convention; keep it.
        self.assertIn("日本語", _embed_json({"t": "日本語"}))


class CallSiteTest(unittest.TestCase):
    """Every inline-script embedding must route through _embed_json."""

    SOURCE = (ROOT / "extract_stats.py").read_text(encoding="utf-8")

    def test_no_partial_escape_remains(self):
        # The upstream "</"-only guard is strictly weaker; it must be gone.
        self.assertNotIn('replace("</", "<\\\\/")', self.SOURCE)

    def test_all_placeholders_are_fed_by_embed_json(self):
        # __DATA_PLACEHOLDER__ is the inline-HTML fallback path
        # (build_inline_html), which is fed the same escaped string.
        for name in ("__SESSION_DATA__", "__FLOW_DATA__", "__PROJECT_DATA__",
                     "__DASHBOARD_DATA__", "__DATA_PLACEHOLDER__"):
            self.assertIn(name, self.SOURCE, f"{name} placeholder disappeared")

    def test_embed_json_used_at_least_five_times(self):
        # dashboard, locale, session, flow, project
        self.assertGreaterEqual(self.SOURCE.count("_embed_json("), 6)


if __name__ == "__main__":
    unittest.main()
```

anchor = '''def generate_dashboard(data):
    """Generate self-contained HTML dashboard with embedded data."""
    data_json = json.dumps(data, ensure_ascii=False)
    # Same </script>-in-string protection as session pages: avoid premature
    # script-tag close when any embedded text contains "</...".

    """Serialize obj for embedding directly inside an inline <script> block.

    Why not escape only "</": text carrying both "<!--" and "<script" (common

    is valid in both JSON and JS string literals so the decoded value is
    unchanged.
    """
    return json.dumps(obj, ensure_ascii=False, **dumps_kwargs).replace("<", "\\\\u003c")


def generate_dashboard(data):
    """Generate self-contained HTML dashboard with embedded data."""
    data_json_inline = _embed_json(data)

```python
# Idle cutoff: a user who walks away mid-turn should not inflate AI time.
_AI_TURN_MAX_MS = 30 * 60 * 1000


def calc_ai_turn_duration(typed_timestamps):
    """Sum user -> assistant round-trip time from (msg_type, ts_ms) pairs.

    A turn opens on the most recent user prompt and closes on the next
    assistant entry. Turns of zero/negative length (out-of-order timestamps in
    merged transcripts) and turns at or beyond the idle cutoff are dropped.
    """
    total_ms = 0
    last_user_ts = None

    for msg_type, ts in typed_timestamps:
        if msg_type == "user":
            last_user_ts = ts
        elif msg_type == "assistant" and last_user_ts is not None:
            turn_ms = ts - last_user_ts
            if 0 < turn_ms < _AI_TURN_MAX_MS:
                total_ms += turn_ms
            last_user_ts = None

    return total_ms


def calc_ai_turn_duration_by_day(typed_timestamps):
    """Same as calc_ai_turn_duration, bucketed by the day the turn started.

    A turn is attributed to its prompt's day, matching daily_message_count, so
    a turn that crosses midnight does not split across two buckets.
    """
    by_day = defaultdict(int)
    last_user_ts = None

    for msg_type, ts in typed_timestamps:
        if msg_type == "user":
            last_user_ts = ts
        elif msg_type == "assistant" and last_user_ts is not None:
            turn_ms = ts - last_user_ts
            if 0 < turn_ms < _AI_TURN_MAX_MS:
                by_day[_day_from_ms(last_user_ts)] += turn_ms
            last_user_ts = None

    return dict(by_day)
```
