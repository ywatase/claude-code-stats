## 決定事項

### 1. 取り込み方式: v1.0.1 を新ベースに再適用

`git merge` / `git rebase` は採らない。独自 7 コミットの全ハンクが、移動または消滅したコードを
指すため、7 件すべてが全面コンフリクトになる。upstream の推奨どおり、v1.0.1 から新ブランチを
切り、各変更を「担当モジュール」へ手で書き直す。

### 2. lint / format 境界の再設定（必須）

計測した実測値:

| 対象 | ツール | 差分 |
|---|---|---|
| `extract_stats.py` + `claudestats_core/` + `tests/` (39 ファイル) | `ruff format` | **37 ファイルが再整形される** |
| `templates/**` (14 ファイル) | `prettier` | **14 ファイルすべてが再整形される** |
| `locales/*.json` | `prettier` | 差分なし |

つまり upstream のコードは当フォークの formatter 設定に適合していない。整形をかけると upstream
との差分が数万行に膨れ、次回以降の取り込みが不可能になる。したがって **upstream 管理下のパスは
formatter から除外する**。

あわせて、グローバル PostToolUse hook (`~/.claude/hooks/quality-loop.sh`) は pre-commit の除外を
尊重せず、Edit/Write したファイルに `ruff format` をかける。既存メモ
（`project_extract_stats_no_edit_tool`）の「`extract_stats.py` は Bash 経由で編集する」という制約は、
**`claudestats_core/`・`tests/`・`templates/` にも拡張する**必要がある。

### 3. `.gitattributes` の CRLF 指定を撤去

v0.8.1 の `extract_stats.py` は CRLF だったが、v1.0.1 は LF（`file` コマンドで確認済み）。
`extract_stats.py text eol=crlf` を残すと逆に差分ノイズを生む。`.gitattributes` は削除する。

### 4. KPI タブの ID は `goals`

- upstream の `tests/test_tab_aliases.py` はタブ ID を `id:\s*'([a-z]+)'` で抽出する。
  アンダースコアを含む `kpi_dashboard` はこの正規表現に掛からない。
- upstream には既に「KPI Dashboard」という名前の別物（ヘッダ直下の KPI ストリップ、`renderKPI()`）
  があり、同名だと混同する。
- よってタブ ID は `goals`、表示ラベルは英 `KPI Goals` / 独 `KPI-Ziele`、内部関数名は
  `renderGoals()` とする。

### 5. AI 稼働時間メトリクスは自前で持つ

upstream の `aggregate.py` には `duration_min`（セッションの開始〜終了の実時間）が既にあるが、
これは当フォークの `ai_duration_min`（user → assistant の往復時間を 30 分未満のみ加算）とは
別物。両方を保持する。

### 6. 日次系列は upstream の `per_day` 規約に合わせる

`aggregate.py` の `session_list.append` はセッション 1 件につき 1 回しか呼ばれない（確認済み）。
日跨ぎセッションは別レコードにはならず、`"per_day"` フィールドに日ごとの `messages` / `models` を
持ち、`dashboard.js` は日次系列を組むときこれを優先する（`templates/dashboard.js` 466 行付近）。

したがって合計値の二重計上は起きないが、日次・週次チャートの粒度を upstream と揃えるため、
`per_day` の各スライスにも `ai_duration_min` を入れる。旧フォーク実装の
`F.sessions.filter(s => s.date === d.date)` は日跨ぎセッションの AI 時間を開始日に全部
寄せてしまうため、そのままは持ってこない。

ターンの帰属日は「プロンプトが出た日」とする（`daily_message_count` と同じ規則。
深夜をまたぐ 1 ターンが 2 日に割れない）。

### 7. upstream への PR は出さない

`<` エスケープは upstream 側の実バグだが、プロジェクトの `CLAUDE.md` が upstream への PR を
禁止しているため、フォーク内に留める。

- タブ 7→5 再編の巻き戻し
- `SESSION_LOG.md` の維持（upstream は `CHANGELOG.md` に移行済み、フォーク側も追随して削除）

## 受け入れ条件

1. `python3 -m pytest tests/ -q` が全件成功（v1.0.1 ベースラインは 252 passed + 22 subtests）
2. 新規追加テストが KPI 目標・AI 稼働時間・`<` エスケープの 3 領域を覆う
3. `python3 extract_stats.py` が実データで完走し、`public/index.html` に KPI Goals タブが出る
4. Playwright E2E 3 spec が新構成に対して成功
5. `pre-commit run --all-files` が成功し、かつ upstream 管理ファイルに整形差分を出さない
   （`git diff v1.0.1 --stat -- extract_stats.py claudestats_core templates tests` が意図した変更のみ）
